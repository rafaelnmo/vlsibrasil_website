Hoje fechamos as quatro operações com a **divisão**, a mais difícil delas. Na multiplicação, todos os produtos parciais podiam ser calculados ao mesmo tempo; na divisão, cada passo **depende do anterior**: só sabemos o que subtrair depois de saber se a subtração anterior "coube". Vamos montar o **divisor com restauração em matriz** (*restoring array divider*), a divisão longa da escola feita com os subtratores do Dia 011 e muxes.

---

## Descrição

O divisor recebe o **dividendo** `in_a` e o **divisor** `in_b`, ambos sem sinal de `WIDTH` bits, e gera o **quociente** e o **resto**, que obedecem a:

```text
in_a = quotient × in_b + remainder,   com 0 ≤ remainder < in_b
```

Por exemplo, `13 / 3`: quociente 4, resto 1, pois `13 = 4 × 3 + 1`.

### A divisão longa em binário

Em decimal, a divisão longa pergunta a cada passo "quantas vezes o divisor cabe aqui?", e a resposta é um dígito de 0 a 9. Em binário é mais fácil: a resposta é só **0 ou 1**, ou seja, "cabe ou não cabe?". O algoritmo, do bit mais significativo para o menos significativo:

1. **Desce** o próximo bit do dividendo, colocando-o à direita do resto atual: `t = {resto, in_a[i]}` (o mesmo que `2·resto + in_a[i]`).
2. **Tenta subtrair** o divisor: `t - in_b`.
3. Se **coube** (`t ≥ in_b`, sem empréstimo): o bit do quociente é `1` e o novo resto é `t - in_b`.
   Se **não coube** (houve empréstimo): o bit do quociente é `0` e o resto volta a ser `t`. Esse "voltar atrás" é a **restauração** que dá nome ao algoritmo.

Depois de `WIDTH` passos, temos todos os bits do quociente, e o que sobrou é o resto.

### E a divisão por zero?

Com `in_b = 0`, a subtração `t - 0` sempre "cabe", então todos os bits do quociente viram `1` e o resto acumula o próprio dividendo: `quotient = 1111` e `remainder = in_a`. Em vez de tratar esse caso à parte, nós o **documentamos**: é exatamente o comportamento que a especificação do **RISC-V** define para a divisão por zero (o processador não gera exceção; o software é que deve verificar o divisor).

## Tabela Verdade

A divisão `13 / 3` (`1101 / 0011`), linha por linha:

![A divisão 13 / 3 passo a passo](/assets/images/100dias/dia_016/dia_016_tabela_verdade.png)

- **Linha 3**: desce o `1` do MSB, `t = 1`. Não cabe 3: `quotient[3] = 0`, o resto continua 1.
- **Linha 2**: desce o `1`, `t = 11` em binário = 3. Cabe! `quotient[2] = 1`, resto `3 - 3 = 0`.
- **Linha 1**: desce o `0`, `t = 0`. Não cabe: `quotient[1] = 0`.
- **Linha 0**: desce o `1`, `t = 1`. Não cabe: `quotient[0] = 0`, resto 1.

Resultado: quociente `0100` = 4, resto `0001` = 1.

## Expressões

![Equações do divisor](/assets/images/100dias/dia_016/dia_016_expressao_booleana.png)

- A primeira linha é a definição da divisão inteira.
- `t` é o resto anterior deslocado com o novo bit do dividendo.
- O bit do quociente é o **inverso do empréstimo** da subtração: sem empréstimo, coube.
- O novo resto é escolhido por um **mux** controlado pelo mesmo bit.

## Diagrama de Circuito

O divisor de 4 bits: uma linha por bit do quociente, cada uma com um subtrator (Dia 011), um mux (Dia 003) e um inversor.

![Divisor em matriz de 4 bits](/assets/images/100dias/dia_016/dia_016_diagrama_circuito.png)

O subtrator de cada linha tem **5 bits** (WIDTH+1), porque `t` tem um bit a mais que o resto: o bit que desceu. O empréstimo do subtrator controla o mux (`1` = não coube, fica `t`; `0` = coube, fica a diferença) e, invertido, vira o bit do quociente.

Repare na dependência em série: a linha 2 só começa depois que a linha 3 decidiu o resto, e assim por diante. O caminho crítico atravessa **todas as linhas**, e em cada uma passa pelo vai-um do subtrator inteiro. Medindo com o Yosys (portas de 2 entradas, sem a ABC):

| WIDTH | Matriz (nosso) | `/` e `%` (padrão do Yosys) |
|-------|----------------|-----------------------------|
| 4     | 114 / 30       | 107 / 42                    |
| 8     | 488 / 78       | 422 / 101                   |
| 16    | 2074 / 191     | 1853 / 242                  |

*(portas / níveis de lógica no caminho crítico)*

Diferente da multiplicação, a divisão não tem atalho fácil, e o próprio Yosys gera uma estrutura em série parecida com a nossa. Por isso, nos processadores, a divisão quase sempre é **sequencial**: um passo por ciclo de clock, levando de 10 a 40 ciclos, enquanto uma multiplicação leva de 1 a 4. Divisores rápidos usam técnicas como SRT (que escolhe o bit do quociente olhando só alguns bits do resto) ou métodos iterativos (Newton-Raphson), que transformam a divisão em multiplicações.

## Código Verilog

O divisor usa o `subtrator` do Dia 011 (e o `somador_cpa` do Dia 007), copiados para a pasta `rtl/`:

```verilog
// ============================================================================
// VLSI Brasil - 100 Dias de RTL
// Dia 016 - Divisor com Restauração em Matriz (Array Divider)
// ----------------------------------------------------------------------------
// Descrição : Divide in_a (dividendo) por in_b (divisor), números sem sinal de
//             WIDTH bits, gerando o quociente e o resto, como na divisão longa
//             feita à mão. Uma linha por bit do quociente, do mais
//             significativo para o menos significativo:
//             1. desce o próximo bit do dividendo: t = {resto, in_a[i]}
//             2. tenta subtrair o divisor (subtrator do Dia 011)
//             3. sem empréstimo: quotient[i] = 1 e o resto vira t - in_b
//                com empréstimo: quotient[i] = 0 e o resto volta a ser t
//                ("restauração")
//             Divisão por zero: quotient = 11...1 e remainder = in_a
//             (o mesmo comportamento definido pelo RISC-V).
// ============================================================================

`timescale 1ns / 1ps

module divisor #(
    parameter WIDTH = 4                         // largura dos operandos
) (
    input  wire [WIDTH-1:0] in_a,               // dividendo
    input  wire [WIDTH-1:0] in_b,               // divisor
    output wire [WIDTH-1:0] quotient,           // quociente
    output wire [WIDTH-1:0] remainder           // resto
);

    // resto[i]: resto parcial depois de processar o bit i do dividendo.
    // resto[WIDTH] é o valor inicial (zero)
    wire [WIDTH-1:0] resto [0:WIDTH];

    assign resto[WIDTH] = {WIDTH{1'b0}};

    // A ordem do laço não importa: cada linha vira hardware próprio, ligado
    // à linha de cima pelo resto[i+1]
    genvar i;
    generate
        for (i = 0; i < WIDTH; i = i + 1) begin : g_linha
            wire [WIDTH:0] t = {resto[i+1], in_a[i]};  // desce o bit i
            wire [WIDTH:0] diff;
            wire           borrow;

            // Subtrai com WIDTH+1 bits, para caber o bit que desceu
            subtrator #(.WIDTH(WIDTH + 1)) u_sub (
                .in_a     (t),
                .in_b     ({1'b0, in_b}),
                .diff     (diff),
                .borrow   (borrow),
                .overflow ()                        // não usado
            );

            // Coube (sem empréstimo)? bit do quociente = 1 e fica a diferença
            assign quotient[i] = ~borrow;
            assign resto[i]    = borrow ? t[WIDTH-1:0] : diff[WIDTH-1:0];
        end
    endgenerate

    assign remainder = resto[0];

endmodule
```

O que há de novo aqui:

- **Fios declarados dentro do `generate`**: `t`, `diff` e `borrow` são declarados **dentro** do bloco `g_linha`. Cada iteração ganha sua própria cópia, com nome hierárquico: `g_linha[2].t`, `g_linha[2].borrow`... Isso evita declarar arrays para sinais que só existem dentro de uma linha.
- **Instância com largura diferente**: `subtrator #(.WIDTH(WIDTH + 1))` cria um subtrator de 5 bits, um a mais que o divisor. O valor de um parâmetro pode ser qualquer expressão constante.
- **Porta de saída não conectada**: `.overflow ()` deixa a saída de estouro do subtrator desligada, pois a divisão sem sinal não precisa dela. Escrever a porta com parênteses vazios deixa claro que ela foi ignorada de propósito (melhor do que omiti-la).
- **A ordem do laço não importa**: as linhas são processadas do bit mais significativo para o menos significativo, mas o laço vai de `0` a `WIDTH-1`. Um `generate` não executa nada: ele só cria hardware, e as ligações entre as linhas (`resto[i+1]` → `resto[i]`) é que definem a ordem do cálculo. Contar para baixo até `-1` com um `genvar` também é rejeitado por algumas ferramentas, então preferimos o laço crescente.

## Testbench

```verilog
// ============================================================================
// VLSI Brasil - 100 Dias de RTL
// Dia 016 - Testbench do Divisor
// ============================================================================

`timescale 1ns / 1ps

module tb_divisor;

    parameter WIDTH = 4;

    // Sinais do testbench
    reg  [WIDTH-1:0] in_a, in_b;
    wire [WIDTH-1:0] quotient, remainder;

    reg  [WIDTH-1:0] q_esperado, r_esperado;

    integer i;
    integer testes = 0;
    integer erros  = 0;

    // Instância do circuito sob teste (DUT - Device Under Test)
    divisor #(.WIDTH(WIDTH)) dut (
        .in_a      (in_a),
        .in_b      (in_b),
        .quotient  (quotient),
        .remainder (remainder)
    );

    // Modelo de referência: os operadores / e %, com o caso especial
    // da divisão por zero (no Verilog, x / 0 dá x)
    task verifica;
        begin
            if (in_b == 0) begin
                q_esperado = {WIDTH{1'b1}};
                r_esperado = in_a;
            end else begin
                q_esperado = in_a / in_b;
                r_esperado = in_a % in_b;
            end
            testes = testes + 1;
            if (quotient !== q_esperado || remainder !== r_esperado) begin
                $display("ERRO: %0d / %0d -> q=%0d r=%0d, esperado q=%0d r=%0d",
                         in_a, in_b, quotient, remainder, q_esperado, r_esperado);
                erros = erros + 1;
            end
        end
    endtask

    // Aplica um teste dirigido, espera 10 ns e mostra o resultado
    task aplica(input [WIDTH-1:0] a, input [WIDTH-1:0] b);
        begin
            in_a = a; in_b = b;
            #10;
            $display(" %t | %3d / %3d | q = %3d  r = %3d", $time, in_a, in_b,
                     quotient, remainder);
            verifica;
        end
    endtask

    initial begin
        // Arquivo de formas de onda para o GTKWave
        $dumpfile("tb_divisor.vcd");
        $dumpvars(0, tb_divisor);

        // Exibe o tempo em ns
        $timeformat(-9, 0, " ns", 6);

        $display("WIDTH = %0d", WIDTH);
        $display("-----------------------------------------");
        $display(" tempo  |   a /   b | quociente e resto");
        $display("-----------------------------------------");

        // Parte 1: testes dirigidos (aparecem nas formas de onda)
        aplica(13, 3);                      // o exemplo do post: q = 4, r = 1
        aplica(12, 4);                      // divisão exata
        aplica(5, 7);                       // dividendo menor: q = 0
        aplica(15, 1);                      // por um
        aplica(15, 15);                     // por ele mesmo
        aplica(9, 0);                       // por zero: q = 11...1, r = a

        // Parte 2: testes fora das formas de onda
        $dumpoff;
        if (WIDTH <= 8) begin
            // Teste exaustivo: todas as 2^(2*WIDTH) combinações
            for (i = 0; i < (1 << (2 * WIDTH)); i = i + 1) begin
                {in_a, in_b} = i;
                #10;
                verifica;
            end
        end else begin
            // 1000 testes aleatórios; divisores pequenos em metade deles,
            // para gerar quocientes grandes
            for (i = 0; i < 1000; i = i + 1) begin
                in_a = {$random, $random};
                in_b = (i % 2) ? ($random & 8'hFF) : {$random, $random};
                #10;
                verifica;
            end
        end

        $display("-----------------------------------------");
        if (erros == 0)
            $display("SUCESSO: %0d testes passaram!", testes);
        else
            $display("FALHA: %0d erro(s) em %0d testes.", erros, testes);

        $finish;
    end

endmodule
```

O modelo de referência usa os operadores `/` e `%` do Verilog, com um cuidado: em Verilog, dividir por zero dá o valor desconhecido `x`, então o caso `in_b = 0` é tratado à parte, com o comportamento que documentamos. Nos testes aleatórios com 32 bits, metade dos divisores é pequena (até 255): se os dois números fossem sempre aleatórios de 32 bits, o quociente seria quase sempre 0 ou 1, e os bits de cima do quociente nunca seriam testados.

## Resumo

- O divisor calcula quociente e resto: `in_a = quotient × in_b + remainder`, com `remainder < in_b`.
- A **divisão com restauração** decide um bit do quociente por linha: desce um bit do dividendo, tenta subtrair o divisor e, se não couber, restaura o resto.
- O bit do quociente é o inverso do empréstimo do subtrator, e um mux escolhe o novo resto.
- Cada linha depende da anterior, por isso a divisão é lenta e quase sempre feita de forma sequencial nos processadores.
- Divisão por zero: `quotient = 11...1` e `remainder = in_a`, como no RISC-V.
- Em Verilog: fios declarados dentro do `generate`, parâmetros com expressões e portas deixadas desconectadas de propósito.

Com isso fechamos o bloco de **circuitos aritméticos combinacionais**: somadores, subtrator, comparador, deslocador, rotacionador, multiplicador e divisor. No **Dia 017** damos um passo enorme: o **contador**, nosso primeiro circuito **sequencial**, com clock e memória. Até amanhã!
