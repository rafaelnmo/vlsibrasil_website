Até agora, todos os circuitos do desafio foram **combinacionais**: as saídas dependiam só das entradas daquele instante. Mude as entradas e, depois de um pequeno atraso, as saídas mudam junto. Hoje damos o passo mais importante do desafio até aqui: nosso primeiro circuito **sequencial**, que tem **memória** e um **clock**. E começamos pelo clássico: o **contador**.

---

## Descrição

Um contador guarda um número e soma 1 a ele a cada pulso de clock. Para isso, ele precisa de duas coisas que nenhum circuito anterior tinha:

- **Memória**: o valor atual precisa ficar guardado entre um pulso e outro. Quem guarda é o **flip-flop**, um elemento que armazena 1 bit. Um grupo de flip-flops que guarda um vetor é um **registrador**.
- **Um instante para mudar**: se o contador somasse 1 "o tempo todo", ele giraria descontroladamente. Os flip-flops só atualizam o valor guardado na **borda de subida do clock**, o instante em que o sinal `clk` passa de `0` para `1`. No resto do tempo, a saída fica parada, não importa o que aconteça na entrada.

O clock é um sinal que alterna entre `0` e `1` em ritmo constante. Com um período de 10 ns, há uma borda de subida a cada 10 ns, ou seja, 100 milhões por segundo: **100 MHz**.

Nosso contador tem mais dois controles:

- **`en`** (*enable*, habilitar): só conta quando `en = 1`; com `en = 0`, mantém o valor.
- **`rst_n`** (*reset*): leva o contador a zero. O `_n` no nome indica que ele é **ativo em nível baixo**: o reset acontece quando `rst_n = 0`. Ele é **assíncrono**: zera o contador **imediatamente**, sem esperar o clock.

Depois do maior valor (`1111` = 15, com 4 bits), a soma `15 + 1 = 16` não cabe em 4 bits, e o contador volta para `0000`. Esse "dar a volta" (*wrap-around*) é exatamente o descarte do vai-um que vimos no Dia 007.

Repare nos dois símbolos novos no diagrama, que fazem parte do padrão dos diagramas de blocos: o **triângulo** marca uma entrada de clock, e a **bolinha** marca um sinal ativo em nível baixo.

## Tabela Verdade

Em um circuito sequencial, a tabela verdade vira uma **tabela de estados**: para cada valor atual (o **estado**), qual será o próximo valor depois da borda de clock. Para um contador de 3 bits:

![Tabela de estados de um contador de 3 bits](/assets/images/100dias/dia_017/dia_017_tabela_verdade.png)

Com `en = 0`, o próximo estado é igual ao atual. Com `en = 1`, é o atual mais 1, e o `111` volta para `000`.

## Mapa de Karnaugh

Olhando cada bit do próximo estado (com `en = 1`) como uma função do estado atual, aparecem padrões conhecidos:

![Mapas de Karnaugh do próximo estado](/assets/images/100dias/dia_017/dia_017_mapa_karnaugh.png)

- **`q1` (próximo)** vale `1` quando `q1` e `q0` são **diferentes**: é a XOR `q1 ⊕ q0`.
- **`q2` (próximo)** é o tabuleiro da XOR de novo, mas entre `q2` e o produto `q1 · q0`: o bit 2 só muda quando `q1` e `q0` estão os dois em `1`.

## Expressões Booleanas

![Expressões do próximo estado](/assets/images/100dias/dia_017/dia_017_expressao_booleana.png)

O padrão geral: **um bit muda (inverte) quando todos os bits abaixo dele valem `1`** e o contador está habilitado. É exatamente o vai-um que se propaga na soma `count + 1`. Num contador de 4 bits, o bit 0 inverte a cada borda, o bit 1 a cada 2, o bit 2 a cada 4 e o bit 3 a cada 8: cada bit tem **metade da frequência** do anterior. Por isso um contador também serve como **divisor de clock**, um assunto que vai voltar mais adiante no desafio.

## Diagrama de Circuito

![Contador: registrador, somador e mux](/assets/images/100dias/dia_017/dia_017_diagrama_circuito.png)

O contador é um laço de realimentação com três peças:

- o **registrador** `count` (4 flip-flops), que guarda o valor atual;
- o **somador** `+1`, que calcula o próximo valor (o mesmo somador dos Dias 005 a 010, com um operando fixo);
- o **mux** controlado por `en`, que escolhe entre manter (`count`) ou contar (`count + 1`).

A saída do registrador volta para a sua própria entrada, passando pela lógica combinacional. Esse é o formato de **todo** circuito sequencial síncrono: registradores guardam o estado, e a lógica combinacional calcula o próximo estado a partir do estado atual e das entradas. A cada borda de clock, o próximo estado vira o estado atual.

E é aí que o atraso dos circuitos combinacionais (que medimos nos Dias 008 a 010) vira **velocidade máxima**: o próximo valor precisa estar pronto e estável na entrada do registrador **antes** da próxima borda. O período do clock precisa ser maior que o atraso do caminho mais lento entre dois registradores.

## Código Verilog

```verilog
// ============================================================================
// VLSI Brasil - 100 Dias de RTL
// Dia 017 - Contador Binário Crescente (Counter)
// ----------------------------------------------------------------------------
// Descrição : Contador de WIDTH bits que soma 1 a cada borda de subida do
//             clock enquanto en = 1. Depois do maior valor (11...1), volta
//             para 0.
//             rst_n: reset assíncrono, ativo em nível baixo (zera o contador)
// ============================================================================

`timescale 1ns / 1ps

module contador #(
    parameter WIDTH = 4                 // largura do contador
) (
    input  wire             clk,        // clock
    input  wire             rst_n,      // reset assíncrono, ativo em 0
    input  wire             en,         // habilita a contagem
    output reg  [WIDTH-1:0] count       // valor atual
);

    // Registrador: só muda na borda de subida do clock,
    // ou imediatamente quando o reset é ativado
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            count <= {WIDTH{1'b0}};     // reset: volta a zero
        else if (en)
            count <= count + 1'b1;      // conta (11...1 + 1 = 00...0)
    end                                 // en = 0: mantém o valor

endmodule
```

O que há de novo aqui (e é muita coisa):

- **`always @(posedge clk ...)`**: um bloco `always` com `posedge` na lista de sensibilidade descreve **flip-flops**. O bloco só "roda" na borda de subida do clock, e os sinais atribuídos dentro dele se tornam registradores. Compare com o `always @(*)` do Dia 003, que descreve lógica combinacional e roda sempre que qualquer entrada muda.
- **`or negedge rst_n`**: incluir o reset na lista de sensibilidade torna o reset **assíncrono**: o bloco também roda quando `rst_n` desce para `0`, sem esperar o clock. O primeiro `if` do bloco precisa testar o reset; esse é o padrão que as ferramentas de síntese reconhecem.
- **Atribuição não bloqueante, `<=`**: dentro de blocos com clock, usamos `<=` em vez de `=`. Com `<=`, **todos os lados direitos são calculados primeiro**, com os valores de antes da borda, e só depois todos os registradores são atualizados ao mesmo tempo. É o comportamento real dos flip-flops, que mudam juntos na borda. A regra prática: **`<=` em lógica sequencial, `=` em lógica combinacional**. Misturar os dois é uma das fontes mais comuns de bugs em Verilog.
- **`output reg`**: `count` é atribuído dentro de um `always`, então é declarado como `reg`. Desta vez, ao contrário do Dia 003, ele **vira** de fato um registrador, porque o `always` tem clock.
- **`else if (en)` sem `else`**: quando `en = 0`, nenhuma atribuição acontece, e o registrador **mantém** o valor. Em lógica com clock isso é exatamente o que queremos (é o mux do diagrama). Lembre que em lógica **combinacional** isso geraria um latch (Dia 003); a diferença é o `posedge`.
- **`count + 1'b1`**: a soma tem a largura de `count` (o maior operando do contexto), então `1111 + 1` dá `0000` e o vai-um é descartado: o contador dá a volta sozinho.

## Testbench

O testbench de um circuito sequencial tem peças novas: um **gerador de clock**, uma sequência de **reset** e a verificação **sincronizada** com o clock.

```verilog
// ============================================================================
// VLSI Brasil - 100 Dias de RTL
// Dia 017 - Testbench do Contador
// ============================================================================

`timescale 1ns / 1ps

module tb_contador;

    parameter WIDTH = 4;

    // Sinais do testbench
    reg              clk = 1'b0;
    reg              rst_n;
    reg              en;
    wire [WIDTH-1:0] count;

    reg  [WIDTH-1:0] esperado;          // modelo de referência

    integer i;
    integer ciclos = 0;
    integer erros  = 0;

    // Instância do circuito sob teste (DUT - Device Under Test)
    contador #(.WIDTH(WIDTH)) dut (
        .clk   (clk),
        .rst_n (rst_n),
        .en    (en),
        .count (count)
    );

    // Gerador de clock: período de 10 ns (100 MHz)
    always #5 clk = ~clk;

    // Modelo de referência: atualizado na mesma borda que o DUT
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            esperado <= 0;
        else if (en)
            esperado <= esperado + 1;
    end

    // Verificação: na borda de descida, longe da borda de subida,
    // quando os dois já se atualizaram
    always @(negedge clk) begin
        ciclos = ciclos + 1;
        if (count !== esperado) begin
            $display("ERRO: t=%0t en=%b -> count=%0d, esperado %0d",
                     $time, en, count, esperado);
            erros = erros + 1;
        end
    end

    // Mostra o valor a cada borda de subida (só na parte dirigida)
    task mostra;
        $display(" %t |   %b    %b  |  %2d  (%b)", $time, rst_n, en, count, count);
    endtask

    initial begin
        // Arquivo de formas de onda para o GTKWave
        $dumpfile("tb_contador.vcd");
        $dumpvars(0, tb_contador);

        // Exibe o tempo em ns
        $timeformat(-9, 0, " ns", 6);

        $display("WIDTH = %0d", WIDTH);
        $display("-----------------------------------");
        $display(" tempo  | rst_n en  | count");
        $display("-----------------------------------");

        // Parte 1: testes dirigidos (aparecem nas formas de onda)
        rst_n = 1'b0; en = 1'b0;            // começa em reset
        #12 rst_n = 1'b1;                   // solta o reset entre as bordas
        en = 1'b1;
        for (i = 0; i < 18; i = i + 1) begin
            @(posedge clk); #1 mostra;      // conta e dá a volta (15 -> 0)
        end
        en = 1'b0;                          // pausa: mantém o valor
        repeat (3) begin
            @(posedge clk); #1 mostra;
        end
        en = 1'b1;
        repeat (3) begin
            @(posedge clk); #1 mostra;
        end
        #3 rst_n = 1'b0;                    // reset assíncrono no meio do ciclo
        #1 mostra;
        #4 rst_n = 1'b1;
        repeat (2) begin
            @(posedge clk); #1 mostra;
        end

        // Parte 2: 1000 ciclos com en aleatório (fora das formas de onda)
        $dumpoff;
        for (i = 0; i < 1000; i = i + 1) begin
            @(posedge clk); #1 en = $random;
        end

        @(negedge clk);
        $display("-----------------------------------");
        if (erros == 0)
            $display("SUCESSO: %0d ciclos verificados!", ciclos);
        else
            $display("FALHA: %0d erro(s) em %0d ciclos.", erros, ciclos);

        $finish;
    end

endmodule
```

- **Gerador de clock**: `always #5 clk = ~clk;` inverte o clock a cada 5 ns, gerando um período de 10 ns. O `reg clk = 1'b0` na declaração define o valor inicial.
- **`@(posedge clk)`**: dentro de um `initial`, espera a próxima borda de subida. É assim que o testbench "anda" de ciclo em ciclo. Depois de cada borda, o `#1` espera 1 ns para mudar as entradas **longe da borda**, evitando que o DUT e o testbench "disputem" o mesmo instante.
- **Verificação na borda de descida**: o bloco `always @(negedge clk)` compara a saída com o modelo no meio do ciclo, quando os dois já se atualizaram e estão estáveis.
- **Modelo de referência**: aqui ele é um contador escrito da mesma forma que o DUT. Para um circuito tão simples, a referência quase inevitavelmente se parece com o projeto. O que ganhamos é a verificação de todos os detalhes ao longo de 1000 ciclos com `en` aleatório. Nos próximos dias, os modelos ficam mais independentes.
- **Reset no meio do ciclo**: o teste aciona o `rst_n` 3 ns depois de uma borda, para conferir que o reset é mesmo assíncrono e não espera o clock.

## Resumo

- Circuitos **sequenciais** têm memória: a saída depende das entradas **e do estado** guardado.
- **Flip-flops** guardam 1 bit e só mudam na borda de subida do clock; um conjunto deles é um **registrador**.
- Todo circuito síncrono é um laço: registradores guardam o estado, e a lógica combinacional calcula o próximo estado.
- O contador é um registrador realimentado por um somador `+1`, com um mux para o `en` e um reset assíncrono.
- Em Verilog: `always @(posedge clk or negedge rst_n)`, atribuição não bloqueante `<=`, e no testbench o gerador de clock e o `@(posedge clk)`.

No **Dia 018** vamos fazer os bits "andarem em círculo": o **contador em anel**, que é um registrador de deslocamento fechado em si mesmo. Até amanhã!
